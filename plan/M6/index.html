    M6 — API + SSE 服务化#

    状态：✅ 完成（2026-08-23） 依赖：M3 (Continuous Batching) · M4 (PagedAttention) · M5 (Prefix Cache) 主层：L4 Server 对齐：vLLM V1 AsyncLLM 架构（单进程简化版）

    0. TL;DR#

    M6 将 inferlite 的推理引擎包装成 OpenAI-compatible HTTP 服务：

    • inferlite serve --model-dir /path/to/qwen3-0.6b 启动服务
    • POST /v1/chat/completions 支持流式/非流式两种模式
    • SSE 流式输出逐 token 推送，格式对齐 OpenAI ChatCompletionStream
    • 支持 temperature / top-k / top-p / repetition_penalty 采样参数
    • Qwen3 thinking 模式的 <think>...</think> 内容映射到 reasoning_content 字段

    核心机制#

    1. AsyncEngine：后台线程运行常驻 engine loop，动态接收请求、逐 token 推送结果
    2. FastAPI + SSE：HTTP 端点接收请求，SSE 流式推送 chunk（data: {json}\n\n）
    3. SamplingProcessor：替代 GreedySampler，支持可配置的采样策略
    4. Pydantic schemas：请求/响应格式对齐 OpenAI spec，保证类型安全

    架构对齐#

    vLLM V1（多进程）：
  API Server Process → AsyncLLM (asyncio) → EngineCore (独立进程) → GPU Workers

inferlite M6（单进程简化版）：
  FastAPI App → AsyncEngine (后台线程) → batch_generate_loop (复用 M3/M4/M5)

    1. 背景：M5 的问题#

    M5 完成了 prefix cache + continuous batching + paged attention，但只能通过 Python API 调用：

    # M5：必须写 Python 代码
from inferlite.engine import batch_generate_paged

results = batch_generate_paged(
    model, sampler, prompts,
    max_new_tokens=100,
    num_blocks=128, block_size=16,
    config=config,
)

    M6 目标：通过 HTTP API 调用，支持 curl / OpenAI SDK / ChatBox 等客户端：

    # M6：curl 直接调用
curl http://localhost:8000/v1/chat/completions \
  -d '{"model":"qwen3","messages":[{"role":"user","content":"Hi"}],"stream":true}'

# OpenAI Python SDK
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="none")
response = client.chat.completions.create(
    model="qwen3",
    messages=[{"role": "user", "content": "Hi"}],
    stream=True,
)
for chunk in response:
    print(chunk.choices[0].delta.content, end="")

    3. 核心设计#

    3.1 架构总览#

    ┌─ Main Thread (FastAPI + uvicorn) ─────────────────┐
│  POST /v1/chat/completions                        │
│    → parse request                                │
│    → engine.submit(prompt_ids, sampling_params)   │
│    → return (request_id, output_queue)            │
│                                                   │
│  if stream=true:                                  │
│    → StreamingResponse(_stream_response)          │
│    → async for token in output_queue:             │
│        yield f"data: {chunk_json}\n\n"            │
│    → yield "data: [DONE]\n\n"                     │
│                                                   │
│  if stream=false:                                 │
│    → await _complete_response                     │
│    → collect all tokens from output_queue         │
│    → return ChatCompletionResponse                │
└───────────────────────────────────────────────────┘
              ↕ queue.Queue (thread-safe)
┌─ Background Thread (Engine Loop) ─────────────────┐
│  while running:                                   │
│    # 接收新请求                                    │
│    while pending_queue.not_empty:                 │
│      req = pending_queue.get()                    │
│      scheduler.submit(req)                        │
│                                                   │
│    # admit + prefill + decode（复用 M3/M4/M5）     │
│    admitted = scheduler.admit()                   │
│    for req in admitted:                           │
│      prefill(req)                                 │
│      output_queue.put(first_token)                │
│                                                   │
│    running = scheduler.running                    │
│    for req in running:                            │
│      decode_step(req)                             │
│      output_queue.put(token)                      │
│      if finished:                                 │
│        output_queue.put(_Sentinel)                │
│        scheduler.mark_finished(req)               │
│                                                   │
│    sleep(0.001)  # 让出 CPU                        │
└───────────────────────────────────────────────────┘

    3.2 线程模型#

    • Main Thread：FastAPI + uvicorn，处理 HTTP 请求
    • Background Thread：engine loop，运行 admit → prefill → decode
    • 通信：queue.Queue（thread-safe），per-request output queue

    为什么用线程而不是 asyncio： - model forward 是 CPU/GPU bound，不适合 asyncio - FastAPI 的 async handler 可以通过 await asyncio.sleep() 轮询 queue，不阻塞 event loop - 线程间通过 queue.Queue 通信，避免 GIL 竞争（model forward 释放 GIL）

    3.3 SamplingProcessor#

    替代 GreedySampler，支持可配置的采样策略：

    class SamplingParams:
    temperature: float = 0.0      # 0 = greedy
    top_k: int = -1               # -1 = 不过滤
    top_p: float = 1.0            # 1.0 = 不过滤
    repetition_penalty: float = 1.0  # 1.0 = 不惩罚
    seed: int | None = None       # 可复现采样

class SamplingProcessor:
    def __call__(self, logits: [B, V]) -> [B, 1]:
        # 1. repetition penalty（对已生成 token 降权）
        # 2. temperature scaling
        # 3. top-k filtering
        # 4. top-p (nucleus) filtering
        # 5. softmax → multinomial sample

    接口兼容：__call__(logits) -> [B, 1]，可直接替换 GreedySampler。

    3.5 思维链映射#

    Qwen3 thinking 模式输出：

    <think>Let me think step by step...</think>
The answer is 42.

    M6 提取 <think>...</think> 内容，映射到 reasoning_content 字段：

    def _split_thinking(text: str) -> tuple[str, str | None]:
    """提取 <think>...</think> 内容。"""
    if "<think>" not in text:
        return text, None

    # 找到最后一个完整的 <think>...</think>
    pattern = re.compile(r"<think>(.*?)</think>", re.DOTALL)
    matches = list(pattern.finditer(text))

    if not matches:
        # 未闭合的 </think>
        if "<think>" in text:
            start = text.index("<think>") + len("<think>")
            return "", text[start:]
        return text, None

    # 提取最后一个 think 块
    last = matches[-1]
    reasoning = last.group(1).strip()
    content = text[:last.start()] + text[last.end():]
    return content.strip(), reasoning

    非流式响应：

    {
  "choices": [{
    "message": {
      "role": "assistant",
      "content": "The answer is 42.",
      "reasoning_content": "Let me think step by step..."
    }
  }]
}

    流式响应暂不推送 reasoning_content（简化实现），全部作为 content 输出。

    8. ADR#

    ADR-01：单进程 + 后台线程（对齐 vLLM V1 简化版）#

    Context：vLLM V1 使用多进程架构（API Server + EngineCore + GPU Workers），适合生产环境。inferlite 是教学项目，需要简化。

    Decision：单进程 + 后台线程。Main Thread 运行 FastAPI，Background Thread 运行 engine loop，通过 queue.Queue 通信。

    Consequences： - 实现简单，无需进程间通信 - GIL 不是瓶颈（model forward 释放 GIL） - 不适合多 GPU / 高并发生产场景 - 后续可扩展为多进程（M12+）

    ADR-02：复用 M3/M4/M5 的 cache + scheduler#

    Context：M3/M4/M5 已实现 FCFS scheduler + PagedCacheAdapter + prefix cache。M6 是否需要重新实现？

    Decision：复用现有组件，AsyncEngine 只负责线程模型 + 动态请求接收。

    Consequences： - 代码复用，避免重复实现 - M3/M4/M5 的测试覆盖自动继承 - 不需要修改 cache / scheduler 核心逻辑

    ADR-03：SamplingProcessor 替代 GreedySampler#

    Context：M3 只有 GreedySampler（argmax）。M6 需要支持 temperature / top-k / top-p / repetition penalty。

    Decision：新增 SamplingProcessor，接口兼容 GreedySampler（__call__(logits) -> [B, 1]），内部实现 5 步采样流水线。

    Consequences： - 接口兼容，可直接替换 GreedySampler - 支持可配置采样策略 - GreedySampler 保留作为快速路径（temperature=0）

    ADR-04：SSE 流式输出（对齐 OpenAI）#

    Context：vLLM 使用 SSE（Server-Sent Events）流式推送 chunk。

    Decision：FastAPI StreamingResponse + SSE 格式（data: {json}\n\n + data: [DONE]\n\n）。

    Consequences： - 对齐 OpenAI ChatCompletionStream 格式 - 客户端可直接使用 OpenAI SDK / EventSource - 简单高效，无需 WebSocket

    ADR-05：reasoning_content 映射（Qwen3 特有）#

    Context：Qwen3 thinking 模式输出 <think>...</think> 标签。OpenAI spec 没有 reasoning_content 字段。

    Decision：提取 <think>...</think> 内容，映射到自定义 reasoning_content 字段（非流式响应）。流式响应暂不推送 reasoning_content（简化实现）。

    Consequences： - 客户端可访问 reasoning_content（如果支持） - 流式输出全部作为 content（简化） - 后续可扩展流式 reasoning_content（可选）
