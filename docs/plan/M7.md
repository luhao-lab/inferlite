# M7 — 推测解码（Speculative Decoding）

> **状态**：📝 规划已确定
> **依赖**：M1–M6（引擎基础 + KV Cache + 调度 + 服务）
> **目标模型**：Qwen3-0.6B（复用现有 dense 模型，无需新模型）
> **主层**：L3 Engine
> **对齐**：vLLM V1 NgramProposer + RejectionSampler · SGLang NGRAM/EAGLE/MTP

---

## 0. TL;DR

M7 让 inferlite 在**不改变输出分布**的前提下，让每次 model forward 产出多个 token，从而加速 decode 阶段。

### 核心机制

```
正常 decode:
  step 1: model([t_99]) → logits_100 → sample → t_100
  step 2: model([t_100]) → logits_101 → sample → t_101
  step 3: model([t_101]) → logits_102 → sample → t_102
  → 3 次 forward，3 个 token

推测解码:
  step 1: Drafter → [t_100, t_101, t_102, t_103, t_104]  ← 快速猜 K=5 个
  step 2: model([t_99, t_100, t_101, t_102, t_103, t_104]) → logits × 6  ← 一次 prefill 验证
  step 3: RejectionSampler → accept 前 N 个，reject 后 K-N 个
  → 1 次 forward，N+1 个 token（N 个接受 + 1 个 bonus）
```

### 实现 3 种 Drafter（由简到难）

| Drafter | 来源 | 需要几个模型 | 加速来源 | 教学价值 |
|---------|------|-------------|----------|----------|
| **n-gram** | prompt + 已生成文本查表 | 1 个 | draft 零成本 | ⭐⭐⭐⭐ |
| **小模型 draft** | 第二个小 LLM（如 Qwen2.5-0.5B） | 2 个（同系列） | 小模型便宜 | ⭐⭐⭐⭐ |
| **EAGLE / MTP head** | 给主模型加 draft head + 训练 | 1 个（+ 训练的 head） | head 比主模型小 | ⭐⭐⭐⭐⭐ |

### 关键保证：**lossless**

推测解码的 rejection sampling 保证输出分布与无推测时完全一致——同样的 seed 下，两种模式生成的文本统计特性相同。这是工程上最漂亮的性质之一。

## 1. 背景：为什么需要推测解码

### 1.1 LLM decode 阶段的瓶颈

Decode 阶段每步只生成 1 个 token，模型 forward 大部分时间在做**内存带宽受限**的小矩阵乘（[1, H] @ [H, H]），计算单元利用率很低。

```
MPS 实测（Qwen3-0.6B bf16）：
  decode 一步: ~70ms
  其中 model forward: ~65ms（93%）
  实际计算量: 极小（batch=1）
  瓶颈: 内存带宽（读权重），不是算力
```

### 1.2 推测解码的核心洞见

**模型 forward 时间和输入 token 数几乎无关（prefill 的并行性）**：

```
1 个 token forward:  70ms
6 个 token forward:  75ms（几乎不变）
```

所以如果能让一次 forward 产出 6 个 token 而不是 1 个，**每 token 摊薄成本从 70ms 降到 12.5ms → 5.6x 加速**。

### 1.3 关键问题：怎么保证 6 个 token 都是对的？

答：**不能保证全对，但可以验证**。用便宜的 drafter 快速猜 K 个，用贵的 target model 一次 forward 验证 K 个，rejection sampling 决定接受前 N 个。

## 3. 技术方案

### 3.1 整体架构

```
engine loop（M3/M6 已有）：
  while not finished:
      # ── 新增：M7 推测解码循环 ──
      draft_tokens = proposer.propose(context)     # T1/T2/T3 之一
      if draft_tokens:
          logits = model([last] + draft_tokens)    # verify（一次 prefill）
          accepted, bonus = rejection_sample(logits, draft_tokens, draft_probs)
          output.extend(accepted + [bonus])
          rollback_kv_cache(num_rejected)
      else:
          # fallback：正常 decode（draft 失败时）
          logits = model([last_token])
          token = sample(logits)
          output.append(token)
```

### 3.2 三种 Drafter

#### 3.2.1 T1: NgramProposer

**思路**：在 prompt + 已生成文本中，找与**当前后缀**最长匹配的 n-gram，然后提取匹配位置后面的 k 个 token 作为 draft。

```
例：
prompt:  "def fib(n): return fib(n-1) + fib(n-2)"
已生成:  "def fib(5) ="

当前后缀: "fib(5)"  ← 不是，是 "fib("（因为刚生成 "("）
查表: prompt 中 "fib(" 出现在 "fib(n):"、"fib(n-1)"、"fib(n-2)" 前
最长匹配: "fib("（长度 4）
提取: 匹配位置后的 token → "n" 或 "n-1" 等
```

**vLLM 实现精华（可借鉴）**：
- KMP 的 LPS (Longest Prefix Suffix) 数组，O(N) 找最长匹配
- 翻转 token 序列后，问题变成"找最长前缀"
- `min_n` 到 `max_n` 的长度范围限制
- `num_speculative_tokens` 个 draft token

**inferlite 简化实现**：
- 教学优先用滑动窗口 O(N × max_n)，不一定要 KMP
- 后期优化可升级为 KMP

#### 3.2.2 T2: DraftModelProposer

**思路**：加载第二个小模型做 K 次 autoregressive forward。

```
例：
target: Qwen3-0.6B
draft:  Qwen2.5-0.5B 或 TinyLlama-1.1B（同系列 tokenizer）

关键约束：两个模型必须共享 tokenizer 和 vocab，否则 token 无法对比
```

**实现要点**：
- 第二个模型独立加载，有自己的 KV cache
- draft 阶段用小模型的 K 次 forward（每次约 20ms）
- verify 阶段用大模型的 1 次 forward（约 70ms）

#### 3.2.3 T3: EagleProposer

**思路**：给主模型加一个轻量 draft head，用主模型最后一层的 hidden state 预测下一个 hidden state，递归 K 次生成 K 个 draft tokens。

```
主模型 Qwen3-0.6B:
  input_ids → embedding → layer_0 → ... → layer_27 → norm → lm_head → logits

EAGLE head（小 MLP，参数量 ~5% 主模型）：
  接在最后一层的 hidden states 上
  → MLP: [H, H] → SiLU → [H, H]  ← 预测下一个 hidden state（不是 logits）

Draft 流程（递归 K 次）：
  h_t = target_model.get_last_hidden_state(context)
  for k in range(K):
      h_{t+1} = eagle_head(h_t)         # 预测下一个 hidden state
      logits = target_model.lm_head(h_{t+1})  # 复用已有 lm_head → token
      token = sample(logits)
      h_t = h_{t+1}  # 递归

训练：
  1. 冻结主模型
  2. 用几十条 prompt 跑主模型，收集 hidden states（h_t, h_{t+1}）
  3. 训练 eagle head（MSE loss）
  4. 几百步就够，Mac 上 10-30 分钟
```

**教学价值最高**：
- 理解 EAGLE 论文的核心思想（"特征比 token 更有预测力"）
- 完整走一遍"设计 head → 训练 → 推理"的闭环
- 理解特征空间的 draft vs token 空间的 draft 的区别

#### 3.2.4 T4: MTPProposer

**思路**：训练多个独立的 MTP head，每个 head 直接从 h_t 预测 +N 位置的 hidden state，避免 EAGLE 递归时的误差累积。

```
T3 EagleProposer（单 head 递归）：
  head(h_t)     → h_{t+1} → token_{t+1}
  head(h_{t+1}) → h_{t+2} → token_{t+2}  ← 依赖上一步，误差累积
  head(h_{t+2}) → h_{t+3} → token_{t+3}

T4 MTPProposer（多 head 独立）：
  head_1(h_t) → h_{t+1} → token_{t+1}
  head_2(h_t) → h_{t+2} → token_{t+2}  ← 直接从 h_t 预测，无累积误差
  head_3(h_t) → h_{t+3} → token_{t+3}
```

**本质是"伪 MTP"**：
- 原生 MTP（如 DeepSeek-V3）在预训练时就内置多个 prediction head
- 我们的 MTPProposer 是外挂多个 head，训练方式和 EAGLE 相同，只是训练数据偏移不同
- head_1 训练数据：(h_t, h_{t+1})，head_2：(h_t, h_{t+2})，head_3：(h_t, h_{t+3})

**训练成本**：K 个 head 需要 K 次训练（可并行），每个 head 训练时间和 T3 相同

### 3.3 Rejection Sampler

**教科书算法（Leviathan et al. 2023）**：

```python
def rejection_sample(draft_tokens, p_target, p_draft):
    """
    draft_tokens: [K] draft 生成的 token ids
    p_target: [K, V] target model 对每个位置的概率分布
    p_draft:  [K, V] draft model 对每个位置的概率分布

    返回：接受的 tokens + 1 个 bonus token
    """
    accepted = []
    for i, token in enumerate(draft_tokens):
        # 接受概率 = min(1, p_target / p_draft)
        accept_prob = min(1.0, p_target[i, token] / p_draft[i, token])

        if random() < accept_prob:
            accepted.append(token)
        else:
            # 拒绝：从修正分布中采样一个 token 作为 bonus
            # 修正分布 = normalize(max(0, p_target - p_draft))
            adjusted = normalize(relu(p_target[i] - p_draft[i]))
            bonus = sample(adjusted)
            return accepted + [bonus]  # 截断 + bonus
    else:
        # 全部接受：额外从 target 分布采样一个 bonus
        bonus = sample(p_target[K])
        return accepted + [bonus]
```

**Greedy 简化版（temperature=0 时可用）**：

```python
def greedy_verify(draft_tokens, target_argmax):
    """greedy 模式不需要概率，直接比 argmax"""
    accepted = []
    for i, token in enumerate(draft_tokens):
        if token == target_argmax[i]:
            accepted.append(token)
        else:
            # 拒绝：用 target 的 argmax 作为 bonus
            return accepted + [target_argmax[i]]
    else:
        # 全部接受：用最后一个位置的 argmax 作为 bonus
        return accepted + [target_argmax[K]]
```

### 3.4 KV Cache Rollback

**关键问题**：draft tokens 中有被拒绝的，要把它们写入的 KV cache 清理掉。

```
draft 阶段写入：
  pos 100 → block 5 写入 slot 3  ✓（被接受）
  pos 101 → block 5 写入 slot 4  ✓（被接受）
  pos 102 → block 5 写入 slot 5  ✗（被拒绝）
  pos 103 → block 6 写入 slot 0  ✗（被拒绝）

rollback：
  adapter.rollback(req_id, num_rejected=2)
  → cur_len -= 2
  → block 6 释放
  → block 5 的 slot 5 标记为可用
```

**与 M5 Prefix Cache 的交互**：
- 被拒绝的 tokens 对应的 block 不能进入 prefix cache（chain hash 会污染）
- rollback 时要调用 `hash_blocks` 重新注册正确的 chain hash

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| n-gram 加速不稳定（自然语言无重复） | 效果差 | 提供 fallback 到正常 decode |
| 小模型 draft 下载麻烦 | T2 延期 | 用 TinyLlama-1.1B（小，易下载） |
| EAGLE 训练不稳定 | T3 失败 | 退化为只验证训练流程，不追求最优 head |
| KV cache rollback 与 prefix cache 冲突 | 数据污染 | 先做 rollback 无 prefix cache 版本，再集成 |
| lossless 保证不成立（采样随机性） | 测试失败 | 用固定 seed + 多次统计验证 |

## 9. 不做的事（明确边界）

### 不做 DFlash（Block Diffusion Drafter）

DFlash 是 2026 年初的新方案，用扩散模型做 drafter（非自回归，一次并行生成 K 个 token）。

不做原因：
- 扩散模型是另一个大话题，偏离推理引擎主线
- 需要训练扩散 drafter，不是简单加个 head
- 目前没有小模型支持
- 教学价值有限（本质是"模型训练问题"不是"推理引擎问题"）

**Drafter 接口已经抽象好**：未来如果 DFlash drafter 出现，只需加一个 `class DFlashProposer(Drafter)` 类，引擎完全不用改。

### 不做 MoE 自推测

等 M8 实现 OLMoE 后再做。MoE 自推测需要 `top_k_override` 参数（M8 引入）和量化态计算（M9 引入），放到 M10 做是自然选择。
