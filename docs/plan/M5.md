# M5 — Prefix Caching：相同前缀复用已计算的 KV block

> **状态**：⬜ 未开始
> **依赖**：M4 — PagedAttention
> **主层**：L2 Memory
> **前置**：M4 的 BlockPool + PagedKVCache + block_table 已就位
> **任务卡目录**：[M5-archive/](../tasks/M5-archive/)

---

## 0. TL;DR

M4 实现了 block 分页的 KV Cache 管理，但每个请求的 block 都是独立分配的，即使两个请求有完全相同的 prompt 前缀，也会各自计算一遍 KV。M5 引入 prefix caching：对填满的 block 计算 hash，新请求到来时查 hash 命中，直接复用已缓存的 block 和对应的 KV 数据，跳过重复 prefill。

### 设计原则（基于 vLLM V1）

- **hash-based prefix caching**：满 block 计算链式 hash，新请求逐 block 查 hash 命中
- **LRU 淘汰**：用 `OrderedDict` 实现 O(1) 的 LRU 队列，空闲不足时淘汰最久未用的缓存 block
- **partial hit CoW**：prefix cache 命中落在 block 中间时，拷贝后独占写入
- **beam search 在上层**：不在引擎内 fork，每个 beam 发独立请求，prefix caching 自动处理共享（学 vLLM V1）

---

## 1. 背景：M4 的问题

M4 的 `PagedKVCache` 解决了内存碎片问题（block 按需分配），但没有解决重复计算：

```text
请求 A: prompt = [t0, t1, ..., t99, t100]
请求 B: prompt = [t0, t1, ..., t99, t200]

M4 行为：
  A 计算 KV for [t0..t100]   → 占用 block_0, block_1, ...
  B 计算 KV for [t0..t200]   → 占用 block_5, block_6, ...  (完全重新计算)

M5 目标：
  A 计算 KV for [t0..t100]   → 占用 block_0, block_1, ...  并注册 hash
  B 到来时查 hash 命中 [t0..t99] → 复用 block_0, block_1, ...
    只需计算 [t200] 这一个新 token 的 KV
```

## 3. 核心设计

### 3.1 LRU 淘汰机制

使用 `OrderedDict` 实现 O(1) 的 LRU 队列：

```text
LRU 队列（OrderedDict）：
  front（队头）= 最久未使用 → 优先淘汰
  back（队尾） = 最近使用   → 最后淘汰

操作：
  touch(block_id)     → move_to_end(block_id)      标记"最近使用"
  free(block_id)      → cached_block_lru[block_id]  加入队尾
  _allocate_new_block → popitem(last=False)          弹出队头（最久未用）
```

### 3.2 Block 生命周期

```text
allocate()         → ref=1, 正常使用
hash_blocks()      → hash=abc 注册到 hash_to_block_id
free()             → ref=0, 进 LRU: [3]
  ... 新请求命中 hash=abc ...
touch(3)           → ref=1, 从 LRU 移出
free()             → ref=0, 再进 LRU: [..., 3]  (最近使用，排后面)
  ... 空闲不够，需要分配新 block ...
_allocate()        → LRU front 是 block_7（最久没用）
                      淘汰 block_7，清 hash，分配给新请求
```

### 3.3 核心代码

#### BlockPool（从 BlockPool 升级）

```python
from collections import OrderedDict, deque
from dataclasses import dataclass, field


@dataclass
class Block:
    """物理 block 元数据。"""
    block_id: int
    ref_count: int = 0
    hash: int = -1
    token_ids: list[int] = field(default_factory=list)


class BlockPool:
    """物理 block 的分配、引用计数、prefix caching 和 LRU 淘汰。

    在 M4 BlockPool 基础上增加：
    - hash_to_block_id: 链式 hash → block_id 索引
    - cached_block_lru: LRU 队列（OrderedDict），追踪 ref_count=0 的缓存 block
    - touch(): 缓存命中时 ref_count++ + LRU move_to_end
    - hash_blocks(): 对填满的 block 计算链式 hash 并注册
    """

    def __init__(self, num_blocks: int, block_size: int) -> None:
        self.num_blocks = num_blocks
        self.block_size = block_size
        self.blocks: list[Block] = [Block(block_id=i) for i in range(num_blocks)]
        self.free_block_ids: deque[int] = deque(range(num_blocks))
        # LRU 队列：key=block_id，front=最久未用，back=最近使用
        self.hash_to_block_id: dict[int, int] = {}
        self.cached_block_lru: OrderedDict[int, None] = OrderedDict()

    # ── hash 计算 ──

    @staticmethod
    def compute_hash(token_ids: list[int], prefix_hash: int = -1) -> int:
        """对一个 block 的 token_ids 计算链式 hash。
        prefix_hash 是前一个 block 的 hash，用于保证上下文唯一性。
        相同 token 序列在不同位置会产生不同 hash。
        """
        import xxhash, numpy as np
        h = xxhash.xxh64()
        if prefix_hash != -1:
            h.update(prefix_hash.to_bytes(8, "little"))
        h.update(np.array(token_ids, dtype=np.int32).tobytes())
        return h.intdigest()

    # ── LRU 操作 ──

    def touch(self, block_id: int) -> None:
        """prefix cache 命中，ref_count++ 并更新 LRU 顺序。"""
        block = self.blocks[block_id]
        if block.ref_count == 0:
            # 从无引用变成有引用 → 从 LRU 队列移除
            if block_id in self.cached_block_lru:
                del self.cached_block_lru[block_id]
        block.ref_count += 1

    # ── 分配（带 prefix cache 检查）──

    def can_allocate(self, seq_token_ids: list[int]) -> int:
        """检查 prefix cache 命中数 + 空闲 block 是否够。
        返回命中的 block 数（-1 表示空闲不够）。
        """
        h = -1
        num_cached = 0
        num_needed = (len(seq_token_ids) + self.block_size - 1) // self.block_size
        for i in range(num_needed):
            start = i * self.block_size
            end = min(start + self.block_size, len(seq_token_ids))
            block_tokens = seq_token_ids[start:end]
            # 只对满 block 计算 hash
            if len(block_tokens) < self.block_size:
                break
            h = self.compute_hash(block_tokens, h)
            cached_id = self.hash_to_block_id.get(h, -1)
            if cached_id == -1 or self.blocks[cached_id].token_ids != block_tokens:
                break
            num_cached += 1
        num_new = num_needed - num_cached
        available = len(self.free_block_ids) + len(self.cached_block_lru)
        if available < num_new:
            return -1
        return num_cached

    def allocate_with_cache(
        self, seq_token_ids: list[int], num_cached_blocks: int,
    ) -> list[int]:
        """分配 block table，复用缓存 block。"""
        block_ids = []
        h = -1
        # 复用缓存 block（touch → ref_count++ + LRU move_to_end）
        for i in range(num_cached_blocks):
            start = i * self.block_size
            end = start + self.block_size
            block_tokens = seq_token_ids[start:end]
            h = self.compute_hash(block_tokens, h)
            cached_id = self.hash_to_block_id[h]
            self.touch(cached_id)
            block_ids.append(cached_id)
        # 分配新 block（空闲不够时自动 LRU 淘汰）
        num_total = (len(seq_token_ids) + self.block_size - 1) // self.block_size
        for _ in range(num_cached_blocks, num_total):
            block_ids.append(self._allocate_new_block())
        return block_ids

    def allocate(self) -> int:
        """M4 兼容接口：直接分配一个空闲 block。"""
        return self._allocate_new_block()

    def _allocate_new_block(self) -> int:
        """分配新 block。优先用真正空闲的，不够则淘汰 LRU 最久未用的缓存 block。"""
        if self.free_block_ids:
            block_id = self.free_block_ids.popleft()
        elif self.cached_block_lru:
            # 淘汰 LRU front（最久未用）
            block_id, _ = self.cached_block_lru.popitem(last=False)
            block = self.blocks[block_id]
            # 清除旧 hash
            if block.hash != -1:
                if self.hash_to_block_id.get(block.hash) == block_id:
                    del self.hash_to_block_id[block.hash]
                block.hash = -1
                block.token_ids = []
        else:
            raise RuntimeError("No free blocks available")
        self.blocks[block_id].ref_count = 1
        return block_id

    # ── 释放（延迟淘汰 + LRU）──

    def free(self, block_id: int) -> None:
        """释放 block。ref_count 降为 0 时不立刻清 hash，加入 LRU 队列等复用。"""
        block = self.blocks[block_id]
        assert block.ref_count > 0
        block.ref_count -= 1
        if block.ref_count == 0:
            if block.hash != -1:
                # 有 hash → 进 LRU 队列（最近释放，排到队尾）
                self.cached_block_lru[block_id] = None
            else:
                # 无 hash → 直接归还空闲池
                self.free_block_ids.append(block_id)

    # ── hash 注册 ──

    def hash_blocks(
        self, block_ids: list[int], seq_token_ids: list[int],
        num_full_blocks: int,
    ) -> None:
        """prefill/decode 完成后，对填满的 block 计算链式 hash 并注册。"""
        h = -1
        for i in range(num_full_blocks):
            start = i * self.block_size
            end = start + self.block_size
            block_tokens = seq_token_ids[start:end]
            h = self.compute_hash(block_tokens, h)
            block = self.blocks[block_ids[i]]
            block.hash = h
            block.token_ids = block_tokens
            self.hash_to_block_id[h] = block_ids[i]

    @property
    def num_free_blocks(self) -> int:
        return len(self.free_block_ids)

    @property
    def num_cached_blocks(self) -> int:
        return len(self.cached_block_lru)
```

#### Partial Hit CoW

当 prefix cache 命中了一个 block 的一部分（命中 token 数不是 block_size 的整数倍），需要 CoW：

```python
class PagedKVCache:
    # ... M4 代码 ...

    def handle_partial_hit(
        self, request_id: str, block_idx: int,
        source_block_id: int, hit_tokens: int,
    ) -> int:
        """prefix cache 命中了 block 的一部分。
        分配新 block，拷贝 source 的 KV，替换 block_table。
        返回新 block_id。
        """
        # 分配新 block
        new_block_id = self.block_pool._allocate_new_block()
        # 拷贝 KV 数据
        for layer in self.layers:
            layer.k[new_block_id] = layer.k[source_block_id].clone()
            layer.v[new_block_id] = layer.v[source_block_id].clone()
        # 释放 source 的引用
        self.block_pool.free(source_block_id)
        # 替换 block_table
        table = self.block_tables[request_id]
        table.block_ids[block_idx] = new_block_id
        return new_block_id
```

#### Beam Search（上层实现）

参考 vLLM V1，beam search 不在引擎内 fork，而是发独立请求：

```python
# entrypoints/beam_search.py（概念代码）

def beam_search(engine, prompt, beam_width, max_tokens):
    all_beams = [Beam(prompt_tokens=prompt, cum_logprob=0)]

    for step in range(max_tokens):
        # 每个 beam 是一个独立请求
        results = []
        for i, beam in enumerate(all_beams):
            result = engine.generate(
                prompt=beam.all_tokens,   # prompt + 之前生成的 token
                max_new_tokens=1,
                request_id=f"beam-{step}-{i}",
            )
            results.append(result)

        # 选 top-k beam
        # prefix caching 自动共享相同前缀的 block
        all_beams = select_top_beams(results, beam_width)

    return all_beams
```

每个 beam 的 prompt = 原始 prompt + 已生成的 token。prefix caching 会自动发现所有 beam 共享相同的前缀 block，直接复用（hash 命中），不需要显式 fork。

## 7. ADR 决策

### ADR-01：使用 OrderedDict 实现 LRU

**Context**：LRU 淘汰是 prefix caching 的关键组件。可选方案：手写双向链表、OrderedDict、deque + dict。

**Decision**：使用 `collections.OrderedDict`。内部是双向链表 + dict，`move_to_end` 和 `popitem` 都是 O(1)。

**Consequences**：
- ✅ 代码最简洁，教学友好。
- ✅ 性能等价于手写 LRU。
- ❌ 不如 vLLM V1 的分级 evictor 灵活。

### ADR-02：beam search 在上层以独立请求实现

**Context**：vLLM V0 在引擎内 fork + CoW；vLLM V1 在上层发独立请求 + prefix caching 自动共享。

**Decision**：学 vLLM V1，beam search 不在引擎内 fork，引擎不需要感知 beam search。

**Consequences**：
- ✅ 引擎更简单，不需要 fork/CoW 机制。
- ✅ prefix caching 自动处理共享，代码更优雅。
- ❌ 每步每个 beam 都是独立请求，开销略大（教学版可接受）。

### ADR-03：链式 hash 保证上下文唯一性

**Context**：相同 token 序列在不同位置应有不同 hash（避免误命中）。

**Decision**：每个 block 的 hash = f(prefix_hash, token_ids)，链式计算。

**Consequences**：
- ✅ 不同位置的相同 token 产生不同 hash，避免误命中。
- ✅ 前缀匹配天然支持链式 hash。
- ❌ 不能只匹配后缀（必须是前缀命中）。
